# Clock-in System — Organisation Presentation Guide

This document is a **content and structure guide** for presenting the Clock-in System to your organisation. Use it to build slides, talking points, and demos. It covers: what problems the system solves, how to use it, which scenarios it supports, how it improves organisational efficiency, and how it makes day-to-day work easier for staff.

## 1. Presentation Structure (Suggested Flow)

Suggested order for a 20–30 minute presentation (adjust for your time slot):

| # | Section | Purpose | Suggested time |
|---|--------|---------|----------------|
| 1 | **Opening: The challenge** | Set context — attendance, fairness, compliance | 2 min |
| 2 | **Problems we face today** | List pain points (manual, inconsistent, no visibility) | 3 min |
| 3 | **Introducing the Clock-in System** | One-sentence pitch + what it is | 2 min |
| 4 | **How it works (high level)** | QR + token, roles, one place for everything | 3 min |
| 5 | **Scenarios we support** | Remote, overtime, leave, holidays, multiple sites | 4 min |
| 6 | **How to use it (by role)** | Quick walkthrough for Employees, Supervisors, HR | 5 min |
| 7 | **Benefits for the organisation** | Time saved, data, compliance, fairness | 3 min |
| 8 | **Benefits for staff** | Simplicity, transparency, less admin | 3 min |
| 9 | **Next steps** | Rollout, training, support | 2 min |

**Tip:** If the audience is mixed (management + staff), emphasise **Section 7** for leaders and **Section 8** for employees, and keep **Section 5** practical so everyone leaves knowing what they will do day to day.

## 2. Problems the System Aims to Solve

Use this to set the “why we need this” part of the presentation.

### 2.1 Attendance and Time Tracking

- **Manual or paper-based clock-in** — Easy to lose, hard to audit, no single source of truth.
- **No proof of location** — Hard to know if people are on-site when they say they are; disputes are difficult to resolve.
- **Inconsistent rules** — Different departments or sites may apply start times, grace periods, or overtime differently.
- **Late arrivals and absenteeism** — No clear, timely view of who is late or absent; follow-up is reactive.

### 2.2 Overtime and Leave

- **Overtime not approved in a clear flow** — Who approves? When? No trail from request → supervisor → HR.
- **Leave on spreadsheets or email** — Balances and requests scattered; HR spends time chasing information.
- **Unclear balances** — Staff don’t easily see their own leave; HR gets repeated “how many days do I have?” questions.
- **Holidays and exceptions** — Confusion about whether someone should clock in on a public holiday or how to treat special cases.

### 2.3 Administration and Compliance

- **HR time spent on admin** — Compiling timesheets, checking locations, reconciling leave, generating reports manually.
- **No audit trail** — Who clocked in where and when; who approved what; hard to demonstrate fairness or compliance.
- **Remote or multi-site work** — No standard way to allow clock-in from approved off-site locations (e.g. client sites, fieldwork).

### 2.4 Fairness and Transparency

- **Perception of unfairness** — “Some people get away with X” — no visible, consistent rules or data.
- **Staff uncertainty** — “Am I late?” “Did my leave get approved?” “Can I work overtime?” — answers buried in email or verbal.

**Talking point:**  
*“We needed one system that gives us accurate attendance, clear approval flows for overtime and leave, and a single place where both the organisation and staff can see what’s happening.”*

## 3. How the System Solves Them

Map each problem area to what the system does. Use this for a “solution overview” slide or two.

| Problem | How the system helps |
|--------|------------------------|
| Manual / paper clock-in | **Digital clock-in** via QR code (on-site) or one-time token (approved off-site). All events stored with timestamp and optional GPS. |
| No proof of location | **GPS at clock-in** (for QR). Location checked against a list of acceptable sites; out-of-range clock-ins can be flagged for HR review. |
| Inconsistent rules | **Central work schedule** (start/end, late grace, auto clock-out). Same rules for everyone; configurable in one place. |
| Late / absent visibility | **Automatic flagging** (e.g. late arrival, unexpected location). HR sees a dedicated list to review and act on. |
| Overtime approval chaos | **Structured workflow:** Employee requests → Supervisor approves/rejects → HR can issue overtime token. All tracked in the system. |
| Leave on spreadsheets | **Leave in the system:** Request, approve/deny, balances per type (paid, sick, maternity, etc.), extensions, early return. |
| Unclear leave balances | **Employee dashboard** shows balances; HR can set policies and adjust where needed. |
| Holidays and exceptions | **Holidays calendar** — no normal clock-in on those days; overtime still possible. Policies can support different leave types. |
| HR admin burden | **One place** for users, departments, locations, tokens, flags, leave, overtime. **Reports** (attendance, leave, overtime) exportable for payroll or audits. |
| No audit trail | **Every clock-in/out, request, and approval** is stored with who did it and when. |
| Remote / multi-site | **Acceptable locations** (with radius). **Token requests** for staff who need to clock in from an approved off-site location; HR approves and can issue a token. |
| Fairness and transparency | **Same rules for everyone;** staff see their own data (attendance, leave, requests); HR can show clear, consistent processes. |

**Talking point:**  
*“One platform: clock-in, location check, overtime approvals, leave, and reporting — so we spend less time on admin and more on supporting our people and operations.”*

## 4. Scenarios the System Accommodates

Use these as “real situations we support” to make the system concrete.

### 4.1 Standard On-Site Day

- Employee arrives at the office (or approved site).
- They open the app on their phone, scan the **QR code** displayed at reception (or on a screen).
- System records clock-in with **time and GPS**; if within an approved location and within the grace period, no flag.
- At end of day they **clock out** manually, or the system **auto-clocks them out** based on the work schedule.

**Message:** Simple, fast, and consistent for a normal workday.

---

### 4.2 Working From an Approved Off-Site Location

- Employee is at a client site or other approved location that HR has added to the system.
- They **request a clock-in token** (select location, give a short reason).
- HR **approves** the request; system can **generate a token and even auto clock them in**.
- Employee can use the token to clock in from that location (or already be clocked in after approval).

**Message:** We support flexible work while keeping a clear record and approval.

---

### 4.3 Overtime

- Employee knows they will work overtime on a given date.
- They **submit an overtime request** (reason + date).
- **Supervisor** sees the request and approves or rejects (with optional reason).
- If approved, **HR** can **generate an overtime token**; when the employee uses it, they are clocked in as **overtime** (e.g. not auto-clocked out at normal end time).
- On **public holidays**, normal clock-in can be disabled; overtime token is the way to record work.

**Message:** Overtime is visible, approved in a proper chain, and recorded correctly.

---

### 4.4 Leave (Annual, Sick, Other)

- Employee **submits a leave request** (type, dates, description). System can calculate working days (e.g. excluding weekends/holidays).
- **HR** reviews and **approves or denies** (with optional note).
- On approval, **leave balance** is deducted; employee sees updated balance on their **dashboard**.
- If they return **early**, they (or HR) can **log early return**; unused days can be credited back.
- If they need **more time**, they can **request an extension**; HR reviews again.

**Message:** Leave is in one place — request, approval, balance, and extensions — with less back-and-forth.

---

### 4.5 Public Holidays

- HR maintains a **holiday calendar** (e.g. Heritage Day, company shutdown).
- On those dates, **normal QR/token clock-in is blocked** (so we don’t expect people to “clock in” when the office is closed).
- **Overtime** (e.g. essential staff) is still possible via the **overtime request → approval → overtime token** flow.
- **Leave and attendance reports** can treat holidays correctly (e.g. not count them as absent days).

**Message:** The system respects holidays and keeps rules clear.

---

### 4.6 Multiple Sites / Departments

- HR can define **multiple acceptable locations** (different offices, sites, radius per site).
- Employees clock in at **any approved location**; GPS is checked against that list.
- **Departments** are in the system; reports and filters can be by department.
- **Supervisors** see and approve overtime for **their team**; HR sees the whole organisation.

**Message:** One system for all sites and teams, with clear structure and controls.

---

### 4.7 Something Unusual (Late, Wrong Location, Dispute)

- If someone clocks in **late** (after grace period) or **outside any approved location**, the event can be **automatically flagged** (e.g. “LATE_ARRIVAL”, “UNEXPECTED_LOCATION”).
- If someone **leaves significantly earlier than the normal end of day**, the system can **record an early departure** with a short reason from the employee, and flag it for review.
- **HR** sees a **Flags** list, can review, **dismiss** the flag, optionally **add the location** as acceptable (e.g. new site), and see any **early-departure reasons** provided by staff.
- Full **clock history** (who, when, where, method) is available for investigations or disputes.

**Message:** We have visibility and a process for exceptions, not just “normal” days.

## 5. How to Use the System (By Role)

Use this for a “how you will use it” section. Keep it short in the presentation; you can hand out a one-page cheat sheet later.

### 5.1 Employees

**Login:** Email + password (and “Remember me” if offered).

**Daily use:**

1. **Clock in**  
   - **On-site:** Open app → Scan QR (camera may ask for location permission).  
   - **Off-site (with approval):** Enter the **one-time token** HR gave you (e.g. after approving your token request).
2. **Clock out**  
   - Use **Clock out** in the app before leaving (or you may be auto-clocked out at configured end time).
3. **Dashboard**  
   - See **today’s status**, **leave balances**, **upcoming holidays**, and **recent activity**.

**When you need something:**

- **Overtime:** Submit an **Overtime request** (reason + date). Your supervisor approves; then HR may issue an overtime token for that day.
- **Leave:** Submit a **Leave request** (type, dates, description). HR approves or denies; you see status and balances on your dashboard.
- **Work from another location:** Submit a **Token request** (choose location, reason). When HR approves, you may get a token to clock in from there (or be auto-clocked in).
- **Early return from leave:** Use **Early return** on your leave request (actual return date + reason).
- **Extend leave:** Use **Request extension** on the same leave request (extra days + reason); HR reviews.

**Where to look:** Dashboard, Clock history, Overtime requests, Leave requests.

---

### 5.2 Supervisors

**Everything an employee can do**, plus:

1. **Team view**  
   - See who is clocked in today, who has requested overtime, and basic team attendance.
2. **Overtime approvals**  
   - See **overtime requests from your team**; **Approve** or **Reject** (with optional reason). After you approve, HR can issue the overtime token.
3. **Dashboard**  
   - Team stats, pending overtime count, today’s attendance snapshot.

**Message for the presentation:**  
*“Supervisors stay in control of their team’s overtime without handling paperwork; everything is in the system and visible to HR.”*

---

### 5.3 HR

**Full administration.** Use the **HR dashboard** and the **hubs** (Workforce, Attendance, Leave, Overtime, Reports).

**Workforce (employees & departments):**

- Add/edit/deactivate **employees** (name, email, role, department, etc.).
- Create/edit **departments** and assign people.

**Attendance (clock-in, flags, locations, tokens):**

- **Clock history** — View and filter by person, date range.
- **Flagged events** — Review late or unexpected-location clock-ins; dismiss or add location as acceptable.
- **Locations** — Add/edit **acceptable clock-in locations** (name, lat/long, radius). Needed for QR and token requests.
- **Tokens** — **Generate one-time tokens** for a specific employee (regular or overtime). View and manage **token requests** (approve/reject; approval can create a token and optionally clock the employee in).

**Leave (requests, policy, holidays, schedule):**

- **Leave requests** — Approve/deny; log early return; review **extension requests**.
- **Leave policy** — Define leave types (e.g. paid, sick, maternity) and default days; adjust balances if needed.
- **Holidays** — Add/edit public holidays and company closure dates.
- **Work schedule** — Set expected start/end, late grace minutes, auto clock-out buffer.

**Overtime:**

- See all **overtime requests** and their status; for supervisor-approved requests, **generate overtime tokens** when appropriate.

**Reports:**

- **Attendance** — Who was present/absent, hours, by month/department; **export CSV**.
- **Leave** — Leave usage and balances; **export CSV**.
- **Overtime** — Overtime requests and status; **export CSV**.

**Message for the presentation:**  
*“HR has one place to manage people, places, time, and leave — and to pull reports for payroll or audits without chasing spreadsheets.”*

## 6. Organisational Efficiency Benefits

Use this for the “why this is good for the organisation” slide(s).

### 6.1 Time and Cost Savings

- **Less manual timesheet and leave admin** — Clock-in and leave are digital and centralised; HR spends less time compiling and reconciling.
- **Faster reporting** — Attendance, leave, and overtime reports are in the system and exportable (e.g. CSV) for payroll or audits.
- **Fewer “where is …?” questions** — Clock history and flags give a clear view of who was where and when.
- **Structured approvals** — Overtime and leave follow a defined path (employee → supervisor → HR where relevant), reducing ad hoc emails and delays.

### 6.2 Better Data and Decisions

- **Single source of truth** — One system for attendance, leave, overtime, and locations.
- **Audit trail** — Who clocked in/out when and how; who approved what; supports fairness and compliance.
- **Visibility** — Dashboards and reports by department, period, and type (attendance, leave, overtime).
- **Flags** — Exceptions (late, wrong location) are surfaced for review instead of being missed.

### 6.3 Consistency and Compliance

- **One work schedule** — Same start/end and grace rules for everyone (configurable in one place).
- **Clear leave policy** — Types, default days, and balances in the system; approvals and refusals recorded.
- **Holidays** — Consistently applied (no normal clock-in; overtime via process).
- **Location control** — Only approved locations accepted for clock-in (with optional GPS check); supports remote/work-from-other-sites in a controlled way.

### 6.4 Scalability and Flexibility

- **Multiple locations and departments** — Add sites and teams without a new process per site.
- **Remote and hybrid** — Token requests and acceptable locations support off-site work with approval and record-keeping.
- **Overtime and holidays** — Clear process for exceptions (e.g. essential staff on public holidays).

**Talking point:**  
*“We get less admin, better data, consistent rules, and a system that can grow with us — whether we add more sites, more people, or more flexible work patterns.”*

## 7. Worker-Friendly Benefits

Use this for the “why this is good for you” message to staff.

### 7.1 Simplicity

- **One app, one login** — Clock in, request leave, request overtime, see balances in one place.
- **QR scan or token** — Two simple ways to clock in depending on where you work.
- **Auto clock-out** — You don’t have to remember to clock out at end of day (if the organisation uses it).

### 7.2 Transparency

- **Your dashboard** — See your leave balances, today’s status, recent clock-ins, and request status.
- **Your history** — Full view of your own clock-in/out and leave history.
- **Clear status** — Know when a request is pending, approved, or rejected, and why (if a note was added).

### 7.3 Less Back-and-Forth

- **Leave and overtime in the system** — No need to chase email or paper; submit once, check status in the app.
- **Extensions and early return** — Request leave extension or log early return in the same place as the original leave.
- **Token requests** — Request permission to clock in from another location; when approved, you get a token (or are clocked in) without extra steps.

### 7.4 Fairness and Clarity

- **Same rules for everyone** — Start time, grace period, and leave types are defined and visible.
- **Holidays** — Clear when the office is closed and when overtime is allowed.
- **Your data** — You can see your own attendance and leave; disputes can be based on recorded data.

### 7.5 Flexibility Where the Organisation Allows It

- **Multiple sites** — If your workplace has several approved locations, you can clock in at any of them.
- **Approved off-site** — When HR approves a token request, you can work from an approved location (e.g. client site) and still clock in properly.
- **Overtime** — One request; supervisor and HR handle approval and token in the system.

**Talking point:**  
*“The system is built so that your part is simple: clock in, request what you need, and see your own information in one place — while the organisation gets the control and reporting it needs.”*

## 9. Demo Suggestions

If you have 5–10 minutes for a live demo:

1. **Login** as HR (or a test HR user) — show dashboard and navigation.
2. **Show the QR code** (e.g. on HR dashboard or attendance area) and briefly explain: “Employees scan this to clock in on-site.”
3. **Employee view** — Switch to an employee (or open incognito with employee credentials). Show: Dashboard (balances, today’s status), “Scan QR” or “Enter token”, Clock out, and maybe one **Leave request** or **Overtime request**.
4. **Supervisor view** (if relevant) — Show team list and one **Overtime approval** (approve a pending request).
5. **Back to HR** — Show: **Flagged events** (if any), **Locations** (one acceptable location on a map), **Leave requests** (approve one), **Reports** (open Attendance or Leave report, show export).

**Fallback:** If live demo is risky, use **screenshots or a short pre-recorded walkthrough** for the same flow.

## 10. Anticipated Questions and Answers

Use these to prepare for Q&A.

| Question | Suggested answer |
|----------|-------------------|
| **Is my location tracked all day?** | No. Location is only used at the moment of clock-in (for QR scan), to check you’re at an approved site. We don’t track you continuously. |
| **What if I forget to clock out?** | The system can automatically clock you out at the end of the configured work day. HR can also correct records if needed. |
| **What if I’m not at an approved location?** | You (or your manager) can submit a **token request** with a reason. If HR approves, you get a token to clock in from that location. |
| **Can I see my leave balance?** | Yes. It’s on your dashboard, and you see it update when leave is approved or when you return early. |
| **What if the app is down?** | Report to IT/HR. We can look at clock history and, if needed, add manual corrections. The goal is to have a reliable system and a clear process for exceptions. |
| **Who sees my data?** | You see your own. Your supervisor sees team attendance and overtime requests. HR sees organisation-wide data for administration and reports. |
| **Is overtime mandatory?** | No. You request overtime; your supervisor and HR approve. If you don’t request or it’s not approved, you’re not expected to work overtime. |
| **What about public holidays?** | Normal clock-in is turned off on holidays. If you need to work (e.g. essential services), you go through the overtime request flow and HR can issue an overtime token. |
| **Can we add more leave types?** | Yes. HR can configure leave types (e.g. compassionate, study leave) and set default days and who they apply to. |
| **How do we add a new office or site?** | HR adds a new **acceptable location** (name, coordinates, radius). Once added, employees can clock in there (or request a token for it if it’s off-site). |
